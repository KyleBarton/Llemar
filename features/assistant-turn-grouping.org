#+title: Group assistant output under one turn heading

* DONE Group assistant output chronologically
One =** Assistant= heading contains a complete user-visible response, including
backend assistant messages and tool round trips. Backend message boundaries
alone no longer create repeated Assistant headings.

The selected design preserves chronological category runs. Earlier alternatives
were category buckets (all tools, then all thinking, then all messages), and
individual tool/continuation headings. Neither was selected.

* Rendering rules
- Keep the existing =Current= / =User= / =Assistant= heading levels.
- Add a sibling =Messages=, =Tools=, or =Thinking= section only when the
  chronological content category changes.
- =Messages= contains individual =Message= subheadings. Consecutive backend
  messages share a category section but have separate message subtrees.
- Assistant prose sits directly beneath =Message=, not inside a drawer.
- =Thinking= contains =:THINKING:= drawers, folded by default when complete;
  preserve the existing show/fold-thinking customization options.
- =Tools= contains one drawer per tool call, labeled =:BASH:=, =:READ:=,
  =:WRITE:=, etc. Additional descriptive labels are not required.
- Ordinary tool drawers start folded. Edit/write drawers stay expanded, with
  complete previews visible. Category sections must not hide these previews.
- Preserve separate argument/result block folding and manual drawer expansion.
- Late and out-of-order tool results update their original drawer; updates do
  not create new chronological category sections.
- A new submitted prompt starts a new grouped response. Tool loops and retries
  do not. History replay groups assistant output between user messages.

* Org response compatibility
Individual =Message= subtrees provide scope for future assistant-authored Org
headings and resources. That future renderer must nest authored headings below
the individual Message root, rather than let them escape into conversation
structure. This feature does not enable raw Org responses or execution; existing
structural escaping remains in place.

See [[file:assistant-org-responses.org][assistant-authored Org content]].

* Compaction and replay
Store exact backend-message boundaries independently of grouped headings.
Compaction can split a response or a category section, so restore the missing
Assistant/category ancestors around retained content. Keep archived source,
retained messages, later generation, and local drafts in their proper trees.
Unknown boundaries continue to produce an explicit limitation instead of a
guessed archive split.

See [[file:compaction.org][compaction history preservation]].

* Verification
Offline mock-pi/ERT coverage includes category transitions, consecutive messages,
multiple tool calls, late/out-of-order results, replay, thinking and ordinary
tool folding, expanded edit/write previews, literal drawer closing delimiters,
new submissions, and compaction within grouped responses/category sections.

Agent-authored Org nesting, more elaborate steering/follow-up presentation, and
live dogfooding remain separate follow-ups; this implementation does not change
pi's event or session formats.
